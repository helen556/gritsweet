# «Видихни» — остаточний промпт для Claude Code

Працюй у поточному репозиторії «Видихни». Реалізуй комплексну переробку існуючого сайту, а не лише план чи демонстраційні заглушки. Прочитай AGENTS.md, package.json, поточні сцени, компоненти, стилі, API та налаштування деплою. Збережи корисну основу, наявне hero-відео й працездатні функції. Не змінюй стек без потреби. Не видаляй сторонні файли чи дані заради збірки.

Цей промпт замінює попередні описи сцен там, де вони суперечать йому. Реалізувати сім сцен: гроші, рюкзак, клубок, пісок і камінці, глина, карта, невисловлене повідомлення. Наліпки «Чужі слова» замінити чатом. Лід, звичайний папір і струмок не додавати як новий обов'язковий обсяг.

## Файли цього пакета

Почни з README.md. Точні назви й призначення зображень наведені в ASSET_MANIFEST.json; використовуй файли assets/ відповідних сцен. Сцена 07_unsaid_message — програмний UI чату, їй не потрібна готова фотографія. Зображення початкового й кінцевого станів — референси; створити рухомі шари й проміжні стани обов'язково. У пакеті немає окремих вирізаних каменів, банкнот без фону, динамічних ниток, фінального розрівняного піску чи доларів: підготуй ці похідні матеріали/геометрію у проєкті, не видавай комплект за готову інтерактивну сцену. Наявне hero-відео використай з репозиторію. Старий прев'ю-архів не включено, щоб не сплутати статичну збірку з вихідним кодом.

## 1. Назва, сенс і перший екран

Назва сайту — «Видихни». На вході одразу:

«Видихни.
Ну давай. Вивалюй усе, що накипіло.
Матюкатись можна.»

«Задовбало» залишаємо для рекламних матеріалів; не робити це додатковим вступним екраном і не затримувати доступ до «Видихни».

Це простір символічної візуалізації: людина вкладає власну історію у фізичну дію на екрані — відкладає тягар, впорядковує хаос, змотує думки, висловлює недоговорене. Не обіцяти лікування, гарантованого полегшення чи вирішення реальних обставин. Короткі теплі тексти на «ти», жива українська, без моралізування. Без обов'язкової реєстрації, балів, таймерів, streaks і примусового проходження до кінця.

Зберегти hero-відео: muted, playsInline, оптимізовані версії й poster, робочий fallback за відмови autoplay. Перший текст і дія доступні відразу, незалежно від відео, AI та WebGL. Не використовувати для hero довільну нову заглушку.

## 2. Матеріали та якість візуалу

Разом із цим промптом надано референси:
- реальні банкноти 500 та 1000 грн;
- фотографія глини;
- звичайна паперова карта Росії та окремий стан у вогні;
- порожній відкритий рюкзак і той самий рюкзак із великими каменями;
- погоджений лоток: камінці змішані з піском, частина тієї самої дошки порожня;
- заплутана бордова пряжа з доступним кінцем і змотаний клубок.

Знайди фактично передані файли, переглянь їх та склади короткий manifest відповідності сценам. Не вигадуй шляхи й не стверджуй, що отримав вкладення, яких немає. Якщо файл відсутній, реалізуй незалежні частини, точно назви потрібний матеріал і не оголошуй візуал завершеним. Прев'ю ZIP зі статичною збіркою не є вихідним репозиторієм: якщо доступна лише збірка, повідом про потребу вихідного коду, не прав мінімізовані chunks як основний спосіб розробки.

Фото є референсами та потенційними текстурами, а не готовими симуляціями. Підготуй окремі рухомі об'єкти, прозорі вирізані шари, маски перекриття, текстури й проміжні стани там, де потрібно. Не використовуй фон фото як частину кожного рухомого предмета. Наявні матеріали мають визначати вигляд, не замінюй їх примітивними SVG-банкнотами, колами, градієнтними плямами або однаковими particles.

Реалістичні фактури, об'єм, освітлення, контактні тіні, вага, інерція, деформація в місці дотику. Єдиний узгоджений стиль: темний графітовий простір, предмети з натуральними матеріалами й читабельний світлий текст. Не пересвічувати й не робити предмети надто темними на телефоні. За потреби використай ліцензовані стокові текстури/моделі; перевір джерело та права, збережи attribution, не завантажуй випадкові зображення з пошуку без перевірки.

## 3. Переходи й визначення теми

Основний шлях: hero → довільний текст → визначення теми → потрібна сцена або короткий вибір дії → взаємодія → м'яке завершення.

Переходи мають бути помітними й просторовими: текст відходить углиб, змінюються світло й фон, предмет входить у сцену з узгодженою перспективою. Поєднати рух камери/маски/шарів; просте opacity/blur не є достатнім результатом. Орієнтовно 500–900 мс, без блокування дії довгими заставками, без стробоскопа та різких спалахів. Reduced motion — спокійний короткий перехід.

Якщо тема однозначна, НЕ показувати повторно обов'язкову анкету категорій. «Мене бісить Росія» → сцена карти або відразу вибір «Рвати / Палити / Знищити». «В мене борг 200 тисяч доларів» → гроші з розпізнаними сумою й валютою, які можна змінити. «Все на мені» → рюкзак. Кнопка «Змінити тему» доступна завжди. За кількох тем — один короткий вибір «З чого почнемо?». За неоднозначності — одне уточнення.

Локальний fallback також має автоматично маршрутизувати однозначні фрази, навіть якщо AI недоступний. Не називати його AI. Пріоритет конкретної теми над загальним «бісить»: війна не повинна перетворюватися на загальну злість. Врахувати заперечення, українську, російську, суржик, відмінювання та лайку. Страх/горе через війну не прирівнювати до бажання палити карту; запропонувати тихішу дію. Не вводити keyword match як універсально точне розуміння.

## 4. Сім сцен

### 4.1. Гроші й борги

Вступ: «Уяви, як ця сума поступово зменшується. Перекладай купюри й дай собі побачити цей момент».
Підказка: «Візьми купюру й перенеси на суму».

Запитати суму та валюту лише якщо відсутні; розпізнані значення можна підтвердити/змінити без повторного вибору теми. Велика читабельна об'ємна сума, окремі реалістичні купюри й пачки. Для гривні використовувати надані фото 500/1000 грн; для USD — впізнавані реалістичні долари з відповідними матеріалами, не видавати гривню за долари. Для інших валют підготувати коректний матеріал або чесний нейтральний варіант.

Купюру захоплюють за конкретну точку, вона гнеться й повертається, відкидає тінь. Після перенесення на ціль сума плавно зменшується, купюра переходить у стопку. Поза ціллю — повернення без списання. Одна дія не списує двічі. Пачка має видиму товщину. Для великих сум доступне «По купюрі / Пачкою»; якщо крок символічно масштабується, явно позначити це, не показувати номінал 100 із незрозумілим списанням 10 000. Фінальний крок точно до нуля, без від'ємного залишку й нескінченного проходження.

Постійна ненав'язлива позначка: «Символічна вправа — реальний борг не змінюється». При завершенні без конфеті й неправдивого «Борг погашено».
Фінал: «Який маленький крок до цього ти можеш зробити насправді?» Записати відповідь необов'язково, локально.

### 4.2. Рюкзак — «Усе на мені»

Вступ: «Подумай, що ти зараз тягнеш на собі. Назви камені, якщо хочеш, і відкладай по одному».
Підказка: «Витягни камінь і поклади поруч».

Звичайний реалістичний відкритий рюкзак із великими окремими каменями. Після «Що ти зараз тягнеш на собі?» запропонувати 3–6 коротких підписів із тексту людини; можна редагувати, додати свої чи залишити без назви. Не вимагати підпису кожного каменя, не вигадувати її особисті проблеми. Підписи — текстові шари сайту, не вмонтовані в фото.

Кожен камінь витягується й переноситься поруч; підпис і тінь рухаються з ним. Передній клапан правильно перекриває камені до підняття. Решта каменів осідає, рюкзак поступово розправляється. Можна необов'язково обрати для вийнятого каменя «Відкласти / Попросити допомоги / Це не моя відповідальність». Не переривати кожен drag анкетою. Не обов'язково спорожнювати весь рюкзак.
Фінал: «Не все потрібно нести саме зараз. Що можеш відкласти на сьогодні?»

### 4.3. Клубок — «Думки по колу»

Вступ: «Подумай про те, що крутиться в голові. Не потрібно розібратися з усім одразу — почни з однієї ниточки».
Підказка: «Підхопи кінець і води пальцем по колу — нитка змотуватиметься».

Спочатку заплутана маса бордової пряжі, не готовий рівний клубочок. Видимий вільний кінець, який легко захопити. Людина тягне нитку, потім круговими рухами пальця змотує її. Заплутана маса скорочується, акуратний цілісний клубок тієї самої пряжі наростає. Динамічна нитка з фактурою, натягом, петлями й тінями з'єднує ці частини. Прогрес залежить від траєкторії й жесту, не таймера. Не вимагати ідеального кола та не карати за різкий рух. Не підміняти всю сцену звичайною лінією за курсором або crossfade двох фотографій.
Фінал: «Можна рухатися по одній думці, по одному кроку».

### 4.4. Пісок і камінці — «Навести лад»

Вступ: «Подумай, що хочеться впорядкувати. Відділяй камінці від піску й знаходь для кожного своє місце».
Підказка: «Перенеси камінці на вільну частину дошки. Потім розрівняй пісок».

Одна дерев'яна дошка/неглибокий лоток. Пісок спочатку ЗМІШАНИЙ із камінцями. Частина цієї самої дошки — вільна дерев'яна зона. Людина дістає камінці й викладає рядочком на вільній зоні, потім розрівнює пісок. Саме цей варіант погоджено; не повертатися до трьох каменів, які вже складені в кутку, не додавати воду.

Кожен камінець — окремий рухомий об'єкт. Після підняття видно заглиблення й осипання піску. Можна самому розміщувати в ряд, без жорсткого примусового snap; делікатне вирівнювання за близького розташування допустиме. Режим розрівнювання локально змінює висоту поверхні та прибирає борозни. Пісок не скидається після кожного жесту; зберегти фактуру й світлотінь. Без обов'язкових написів на каменях.
Фінал: «На що ти можеш вплинути зараз, а що можеш поки залишити?» Відповідь необов'язкова; сцену можна продовжувати.

### 4.5. Глина — «Дати форму»

Вступ: «Якщо важко підібрати слова, спробуй передати цей стан рухом. Мни, тягни й змінюй форму, як тобі хочеться».
Підказка: «Натискай і тягни. Проведи по поверхні, щоб розгладити».

Реалістична сіра глина за наданим фото: фактура, нерівності, товщина, бокове освітлення, тіні. Натискання залишає вм'ятину саме під пальцем, довше утримання поглиблює її. Drag витягує матеріал, стискання змінює форму; накопичені деформації залишаються. Окремий режим «Розгладити» поступово вирівнює поверхню. Не масштабувати розмиту маленьку пляму на весь екран. Підлаштовувати деталізацію до пристрою, не втрачати матеріальність.
Фінал: «Можеш продовжити або зупинитися тут».

### 4.6. Карта — «Злість через війну»

Вступ: «Якщо зараз це про злість через війну — можеш виразити її тут через дію з паперовою картою».

Паперова карта Росії в міжнародно визнаних межах, БЕЗ Криму й усіх окупованих територій України. Не використовувати DeepState-скриншот із військовими позначками. AI-референс не є авторитетною географією: звірити контур із перевіреним джерелом, за потреби виправити, зберігши погоджений вигляд.

Дії: «Рвати», «Палити», «Знищити» (умовний кінематографічний ефект, як у попередньому задумі «ядерки»).
- Розрив слідує за пальцем; нерівні волокнисті краї, товщина паперу, рух окремих шматків і тіні.
- Вогонь починається під пальцем; край темніє, тліє, скручується, полум'я поступово поширюється, утворюються отвори, попіл і дим. Фінальна палаюча картинка — орієнтир вигляду, не миттєва заміна всієї сцени.
- Умовне руйнування змінює сам паперовий об'єкт, без людей, жертв, реальних цілей, практичних інструкцій, натуралістичного насильства, стробоскопа й різкого гучного звуку.

Підказка відповідно до режиму: «Проведи пальцем, щоб розірвати» / «Торкнись місця, звідки почнеться вогонь». Фінал: «Зупинись на мить. Як ти зараз?»

### 4.7. «Те, що не встигла сказати»

ЗАМІНИТИ «Образливі слова» / «Чужі слова» / наліпки.
Вступ: «Напиши те, що хотіла сказати, але не відправила. Тут можна договорити».

Переконливий знайомий екран чату, схожий за логікою на Telegram: поле, кнопка відправлення, бульбашки, час і статуси. Добре адаптований до мобільної клавіатури. За бажанням поле «Кому ці слова?» без вимоги реального контакту. Можна написати після образи, незавершеної розмови або людині, яка загинула; не припускати конкретну історію.

Після натискання бульбашка природно переходить у чат, з'являються послідовно «Доставлено» → «Прочитано», анімовані позначки. Це приватна символічна симуляція, НЕ інтеграція з Telegram. Коротка постійна позначка «Приватна візуалізація · повідомлення нікому не надсилається», пояснення «“Прочитано” — символічний стан цієї вправи». Не створювати враження справжнього отримання, не вигадувати реальний профіль, статус online або відповідь від померлої людини.

Текст повідомлення та звертання залишаються тільки в пам'яті поточної сесії: не відправляти їх у AI, сервер, аналітику, replay або логи. Без постійного збереження за замовчуванням. Кнопки «Написати ще», «Завершити»; можна вийти будь-коли.
Фінал: «Твої слова тепер мають місце. Можеш побути тут стільки, скільки потрібно».

## 5. Реальна інтерактивність і мобільні жести

Ключова вимога: усі відповідні предмети можна РУХАТИ, деформувати й змінювати жестами, а не просто натискати кнопку, щоб показати друге фото. Підготувати потрібні шари та проміжні стани. Готові перший і останній кадри не означають готової механіки.

Використати наявний стек і найпростіший достатній інструмент: CSS/SVG/canvas для доречних деталей, WebGL/Three.js або наявний рушій для деформацій і матеріалів. Не робити весь сайт важкою 3D-сценою. Асинхронно завантажувати кожну сцену, якість адаптувати, DPR обмежувати. Ціль — плавна реакція близько 60 fps на підтримуваному пристрої; виміряти фактично, не заявляти без перевірки.

Pointer Events, pointer capture, pointerup/pointercancel, без подвійного застосування дії. touch-action обмежувати лише активною сценою; сторінка прокручується поза нею. Предмет і ціль видимі над пальцем, tap targets достатньо великі. Resize, орієнтація, safe areas, мобільна клавіатура, фонова вкладка та повторний вхід мають працювати. При виході зупиняти loops, звук, запити, чистити listeners і WebGL ресурси. За context loss дати відновлення або працездатний спрощений варіант, не порожній екран.

Звук вимкнений за замовчуванням або вмикається явним вибором після взаємодії. Вібрація необов'язкова, не покладатися на неї на iPhone. Reduced motion зберігає основні дії, прибирає сильні камерні переходи. Клавіатурна/кнопкова альтернатива drag. У кожній сцені «Заново», «Змінити сцену», «Завершити»; не приховувати вихід під анімацією.

## 6. AI і відмовостійкість

Підключити Cloudflare Workers AI через серверний API поточного проєкту. Браузер не звертається до Cloudflare напряму. У статичному локальному прев'ю серверний endpoint може бути відсутній: тоді локальна маршрутизація працює, статус підключення правдивий. Не видавати static export за перевірене live AI.

Env: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN, CLOUDFLARE_AI_MODEL. Використати приватно налаштовані значення. Раніше оприлюднений токен не використовувати/не відтворювати; потрібен новий приватний токен. Ніяких NEXT_PUBLIC секретів; лише порожні приклади в .env.example і коректний .gitignore. Не просити надсилати секрет у чат.

Перед вибором моделі перевірити офіційну документацію, доступність на Free, квоти й підтримку потрібної відповіді. Не активувати billing/платний тариф. Модель класифікує початковий текст, не генерує код або довільні сцени. Схема JSON: categories, primaryCategory/null, emotion/null, needsClarification, amount/null, currency/null, дозволені sceneIds. Категорії financial_debt, overload, rumination, anger, unsaid_words, control, war_anger, general, needs_support. Мігрувати hurtful_words та старі маршрути на unsaid_words без поламаних переходів. Глина — anger, чат — unsaid_words; конкретні sceneIds звірити з кодом.

Валідовувати enum, типи, довжину, дозволені категорії/сцени й числові діапазони; не виконувати модельний HTML/JS. Ввід — дані, не інструкції; захистити від prompt injection. Кілька тем допустимі, самооцінку confidence не вважати доведеною точністю. Текст чату та редаговані написи сцен НЕ надсилати повторно для класифікації.

Перед AI-аналізом коротко пояснити зовнішню передачу початкового тексту, дати варіант без AI. Не записувати текст переживань, суму, імена, повідомлення або повну відповідь AI в базу, storage, аналітику чи логи. Технічні журнали — лише код помилки, latency, request ID без особистого змісту. Не називати правила/ручний вибір AI-розпізнаванням.

Timeout, обмеження payload, частоти та добового бюджету; rate limit має працювати між serverless-інстансами. Скасування старого запиту й ігнорування запізнілої відповіді після зміни тексту/сцени. За відсутніх env, 401/403, 429, квоти, offline, 5xx, timeout або невалідного JSON — локальна однозначна маршрутизація, інакше короткий ручний вибір. Жодного нескінченного spinner чи втрати доступу до сцен. Повтори обмежені, без зайвих витрат квоти.

Не трактувати «хочу, щоб борг зник» як самопошкодження. За явної безпосередньої небезпеки запропонувати спокійний шлях підтримки замість руйнівної сцени; один класифікатор не є надійною оцінкою ризику. Контакти допомоги не вигадувати, перевіряти для країни.

## 7. Постійні вимоги до сайту й production

- Адаптація 360/390/430 px і desktop: без накладань, горизонтального скролу, обрізаних цифр, предметів чи кнопок. Семантика, labels, alt, контраст, видимий фокус, клавіатура; loading/empty/error/offline стани.
- Оптимізувати фото/текстури, responsive розміри, WebP/AVIF за потреби, шрифти й відео. Явні dimensions, lazy loading нижче hero; LCP не ховати за loader й не lazy-load. Мінімізувати блокуючі CSS/JS, доречний critical CSS, cache/preconnect лише до реально потрібних доменів. Виміряти LCP/CLS/INP; NO_LCP розслідувати.
- Українські metadata, canonical реального домену, Open Graph, sitemap/robots, structured data лише доречні. Підготувати GSC verification через конфігурацію, не вигадувати код й не заявляти індексацію без доступу. Службові та приватні сторінки не індексувати; користувацький текст не публікувати.
- Аналітика — лише загальні події, без змісту, суми, підписів каменів, імен і повідомлень. Не вмикати replay на приватних полях/сценах. Не додавати зайві інтеграції.
- Якщо база/Storage вже є: спочатку схема, grants, RLS, доступ до рядків і колонок, views/RPC/SECURITY DEFINER, права Storage. Мінімальні права, серверна авторизація; без «дозволити все». Не вводити базу для переживань. Зміни міграціями з відкатом, не видаляти дані заради перевірок.
- Якщо вже є адмінка, сесії, форми, заявки, оплата чи бронювання — зберегти й перевірити ключові потоки. Серверна валідація/авторизація, cookies/CSRF за архітектурою, ідемпотентність і транзакції де потрібно, підписи payment webhooks. Сповіщення не є єдиним записом заявки; передбачити повтор доставки. Не додавати ці функції без потреби.
- Перевірити домен/HTTPS, production env, квоти й можливе призупинення сервісів. Аналізувати конкретні крайові випадки й відновлення. Не обіцяти, що ніколи нічого не зламається.

## 8. Порядок роботи та приймання

Спочатку аудит і матеріали, потім виправлення маршрутизації та бази сцен. Довести гроші, рюкзак і пісок до якісної взаємодії, далі клубок, глину, карту й чат. Це порядок, не дозвіл лишити решту заглушками. Якщо роботу розбито на етапи, точно показувати, що завершено й що лишається.

Обов'язкові build/lint/type checks за проєктом. Змістовні перевірки станів та інтеграцій:
- однозначна фраза про Росію не відкриває повторний вибір категорії;
- борг із сумою/валютою, без валюти, малі/великі суми, точний нуль, подвійний drop;
- кілька тем, заперечення, лайка, змішані мови, prompt injection;
- відсутні env, timeout/429/JSON error/offline, повторний та запізнілий запити;
- переміщення окремих каменів, написи, перекриття клапаном, проміжне розвантаження;
- клубок поступово формується від кругового жесту;
- пісок спочатку змішаний, камінці дістаються й викладаються, поверхня реально вирівнюється;
- деформації глини накопичуються й розгладжуються;
- карта має правильні межі, розрив/вогонь починаються від жесту;
- чат має послідовні символічні статуси, текст не виходить у мережу/логи;
- pointercancel, resize, клавіатура, вихід у фон, restart, reduced motion, вимкнений звук, відмова WebGL;
- 404/серверні помилки; мобільний Lighthouse/PageSpeed за доступності, Supabase Security Advisor якщо застосовний; права гостя/користувача/адміна й доступ до чужих даних якщо вони існують.

Зняти скриншоти початкового, проміжного й кінцевого станів та коротку демонстрацію жестів для перевірки механік. Не видавати скриншот за доказ працездатного drag. За наявності нового токена перевірити live AI на вигаданих прикладах. Емулятор не називати перевіркою фізичного iPhone.

У фінальному звіті: працюючі сцени, використані матеріали, перевірки/результати, фактично виміряна продуктивність, env для локального й production середовища, потреба redeploy, чи перевірено live AI, невирішені обмеження. Не оголошувати сайт готовим лише тому, що сторінка відкрилася. Виконай весь доступний обсяг і дай конкретні кроки для частин, заблокованих зовнішнім доступом.
