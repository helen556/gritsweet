# «Видихни»: правки та нові сцени для Claude Code

Працюй у наявному вихідному репозиторії. Виконай зміни повністю: код, матеріали, звуки, мобільні жести, інтеграції та перевірка. Не обмежуйся планом або статичними картинками. Спочатку прочитай AGENTS.md, package.json, існуючі сцени, стилі, API й налаштування деплою. Зберігай погоджене hero-відео й працездатні сцени. Не міняй стек без потреби, не видаляй чужі файли/дані для проходження збірки. Якщо отримав лише статичне прев’ю, потрібен вихідний код: не прав мінімізовані chunks замість репозиторію.

Це пакет змін від 04.10.2026 до попереднього ТЗ. Цей документ має пріоритет у суперечностях. Глина повністю замінюється пупирчастою плівкою. Долари й злоті прибрати. Додати закривання рюкзака, розбивання посуду, свічку, відкривання банки, теплий шлях для суму/самотності, новий текст і анімацію «Видихай». Інші погоджені сцени залишаються. Не додавати всі раніше запропоновані ідеї як обов’язкові нові сцени.

## 1. Обов’язкові референси

У папці references чотири оригінальні PNG, згенеровані й погоджені в цій розмові:

| Файл | Сцена | Що відтворювати |
|---|---|---|
| 01_dishes_and_bottle.png | «Просто бісить» | Кераміка, прозоре скло, стіна, світло, об’єм, характер уламків; цілі предмети / удар тарілки / розбиття пляшки |
| 02_candle.png | «Хочу тиші» / «Сумно й самотньо» | Воскова свічка, ґніт, тепле світло, фактура воску; запалювання / горіння / крупний план |
| 03_bubble_wrap.png | Замість глини | Зліва ціла пакувальна плівка, справа сплющена; прозорість, блиск, заломи, тонкий пластик |
| 04_beverage_can.png | «Хочу паузу» | Бордова алюмінієва банка, конденсат, срібна кришка; закрита / відкривання / відкрита, внизу крупні плани |

Переглянь усі файли до реалізації. Не замінюй затверджені предмети власними довільними ілюстраціями, emoji, плоскими SVG або кольоровими примітивами. Відтворюй форми, пропорції, фактури, світло й композицію. Допускається зміна кадрування для мобільного, без втрати впізнаваності й жесту.

Ці PNG — візуальні референси, а не готові 3D-моделі, окремі текстури, відео чи аудіо. Не показуй storyboard із перегородками як саму сцену. Не використай цілий колаж як фон із невидимими кнопками. Побудуй окремі рухомі об’єкти/маски/геометрію і реальні проміжні стани. Генерація не гарантує механічної точності: для банки виправляй конструктивні деталі згідно з реальною механікою, зберігаючи вигляд. Палець на референсі — демонстрація жесту, у продукті намальовану руку не показувати.

Старі матеріали грошей, рюкзака, пряжі, піску й карти бери з поточного проєкту/попереднього пакета. Їх немає в цьому ZIP; він доповнює, а не замінює весь проєкт. Не вигадуй, що файл є, якщо його немає. Для відсутнього матеріалу назви точну потребу; незалежні зміни виконай.

## 2. Вигляд, який треба довести до готовності

Реалістичні матеріали, глибина, контактні тіні, відблиски, вага, інерція, реакція в місці дотику. Кераміка, скло, віск, алюміній і плівка мають виглядати й звучати по-різному. Зберегти загальний графітовий простір сайту та погоджені акценти. Світлий фон плівки допустимий усередині сцени: прозорість має залишатися читабельною. Не затемнювати предмети до втрати деталей на телефоні.

Для об’ємних сцен використовуй наявний WebGL/Three.js/R3F чи доречну еквівалентну реалізацію; для плівки можливий якісний Canvas із деформацією, шарами й освітленням. Сам вибір бібліотеки не є доказом якості. Важливий результат: палець змінює предмет у конкретному місці. Не підміняй деформацію загальним scale, готовими частинками або crossfade двох фото.

Жест керує дією, а не просто запускає довге відео. Плавне повернення після незавершеного жесту, правильні проміжні стани, жодних повторних спрацьовувань від одного дотику. Чітка зона захоплення; pointer capture, pointercancel, відпускання поза сценою, resize і зміна орієнтації. Обмежуй touch-action лише там, де треба; не блокуй прокручування всього сайту. Клавіатура й кнопка альтернативної дії для людей, які не можуть виконати drag.

## 3. Тексти першого екрана

Назва бренду/логотипу — «Видихни». Великий заголовок у hero — «Видихай.» Заміни «Ну?» цим заголовком. Збережи наявне погоджене hero-відео з muted/playsInline/poster та fallback; ввід доступний незалежно від відео.

Під заголовком:

«Що зараз не дає тобі спокою?
Напиши як є. Матюкатись можна.»

Placeholder: «Що накипіло?»

Коротке пояснення поруч із формою, окремими короткими абзацами:

«Іноді хочеться хоча б на хвилину відкласти все, що тисне. Тут можна надати цьому форму — і щось із нею зробити.

Уяви свою проблему. Вивантаж її каменями з рюкзака, розплутай думки або розбий тарілку з тим, що бісить. А якщо немає сил — просто запали свічку й побудь тут.»

У розгортанні «Як це працює»:

«Це простір для візуалізації: ти бачиш і відчуваєш дію, яку обираєш самостійно. Проблема може залишитися, але, можливо, стане трохи легше — і з’явиться місце для наступного кроку в житті.»

Не обіцяти лікування чи вирішення реальних боргів. Не захаращувати перший екран довгим текстом; на мобільному компактний вступ, доступне розгортання й помітна дія.

Прибрати великий технічний абзац зі скриншота про сервер і Cloudflare. Біля AI-кнопки коротко: «Для підбору сцени текст буде передано сервісу ШІ». Посилання «Як використовується твій текст» відкриває просте пояснення: що саме передається, кому, навіщо, фактичне зберігання й альтернативу без передачі. Не стверджуй «не зберігається» про стороннього провайдера без перевірки. Власний сервіс не має записувати переживання в логи/базу/аналітику. Передача тільки після явної дії, не під час друку. Альтернатива «Обрати самому» завжди доступна.

## 4. Анімація «Видихай»

Слово ніби м’яко видихнули: кожна літера поступово виникає з легкого серпанку, трохи піднімається й стає чіткою. Поява сусідніх літер перекривається, це не друкарська машинка. Повне слово формується приблизно за 1,8–2,4 с, stagger орієнтовно 100–160 мс, тривалість літери 700–1000 мс. М’яке розсіювання, невеликий дрейф, без великих розлітаючих частинок, різких стрибків, спалахів і без примусового звуку дихання.

Після появи заголовок читабельний і спокійний. Один раз за відкриття, не перезапускати при кожному render/вводі/поверненні зі сцени. Зарезервувати габарити, без CLS. Семантичний h1 зі словом повністю для screen reader; анімовані декоративні букви aria-hidden. Prefers-reduced-motion: проста коротка поява всього слова. Не ховати важливий контент/ввід за цією анімацією.

## 5. Прості кнопки й мова

Пройти ВСІ видимі сторінки, підказки, помилки, меню сцен та кнопки. Писати живою зрозумілою українською на «ти». Технічні терміни залишити в документації, не в користувацькому сценарії. Короткі дієслова, без психологічного канцеляриту, повчань та штучних англіцизмів. Не вимагати правильно назвати емоцію.

| Було / зміст | Має бути |
|---|---|
| Визначити тему | Підібрати сцену |
| Обрати сцену вручну | Обрати самому |
| Без передачі | Без ШІ, якщо це саме локальний підбір; ручний вибір окремо |
| Змінити тему | Обрати іншу сцену |
| Reset / Restart | Почати знову або конкретно «Нова плівка», «Нова банка» |
| Надиктувати | Сказати голосом |
| Loading / processing | Підбираємо сцену… |
| AI/network error | Не вдалося підібрати. Обери сцену самостійно |
| Toggle audio | Звук: увімкнено / вимкнено |

Не перейменовувати кнопку без зміни відповідної логіки. У кнопок стану зрозумілі доступні labels. Голосову функцію зберегти, якщо вона є; коректно обробити відмову дозволу та відсутність підтримки.

## 6. Гроші — лише гривні

Повністю прибрати USD/PLN та інші валютні матеріали із цієї сцени, її вибору й завантажень. Одна якісна реалістична гривнева купюра з уже наданих матеріалів; якщо в проєкті є чіткий референс 1000 грн, використовуй його. Не вигадуй номінал/банкноту. Зберегти купюру без обрізань і розмиття, правильні пропорції, згин, тінь та хват за точку пальця. Пачка — той самий матеріал із видимою товщиною.

Сума цієї вправи — в гривнях. Якщо в тексті згадано долари/злоті, не змінюй її мовчки і не конвертуй вигаданим курсом: коротко попроси суму для вправи у гривнях, поясни «У цій сцені використовуємо гривні». Збережи введені слова, не змушуй знову описувати проблему.

Переніс купюру на суму → один раз зменшив залишок. Drop поза ціллю не списує. Сума не нижча нуля, фінальний крок точний. Для великих сум можна «По купюрі / Пачкою», без прихованого масштабування. Ненав’язлива позначка «Це уява. Реальний борг не змінюється». Початок: «Уяви, як ця сума зменшується. Перенось купюри на неї». Без неправдивого «Борг погашено».

## 7. Рюкзак — закрити після розвантаження

Зберегти реалістичне витягування окремих каменів, їх підписи, вагу, перекриття тканиною, осідання решти та можливість відкласти тягар. Додати справжній бігунок і зубці блискавки по краю отвору.

Після вивантаження каменів підказка: «Тепер можна закрити рюкзак». Палець захоплює бігунок і веде по траєкторії блискавки: з’єднується лише пройдена частина зубців, краї тканини сходяться, отвір поступово закривається. Не накладати поверх готову картинку закритого рюкзака. Тихе «з-з-з» звучить тільки під час руху; швидкість/довжина звуку узгоджені з жестом. На кінці делікатний механічний клац.

Відпустив посередині — стан лишився; можна продовжити. Зворотний рух дозволяє розстебнути. Камені не можна витягати крізь закриту тканину. Якщо людина зупиняється раніше, дозволити завершити без примусу вивантажувати все; закривання не має перетинати камені. Альтернативна кнопка «Закрити рюкзак» відтворює ту саму послідовну дію. Фінал: «Не все потрібно нести зараз».

## 8. Пупирчаста плівка ЗАМІСТЬ глини

Глину прибрати з меню, маршрутизації, preload та підказок. Старий sceneId за потреби м’яко перенаправляти на плівку, не ламати посилання/збережений вибір. Назва «Полопати плівку». Коротко: «Можеш нічого не пояснювати. Просто лопай пухирці».

Референс 03: звичайна прозора пакувальна плівка, не силіконовий pop-it, не скляні кульки. Кожен пухирець — окрема взаємодійна комірка. Натискання спочатку локально прогинає купол; до порога можна відпустити, він повернеться. Після порога один раз лопає: купол спадає, мембрана мнеться, змінюються відблиски й тінь. Лопнутий стан зберігається до «Нова плівка».

Короткий впізнаваний сухий «поп» синхронно з розривом, кілька природних варіацій гучності/тембру. Повтор на сплющеному пухирці не відтворює новий розрив. Можна вести пальцем по сусідніх пухирцях, кожен спрацьовує один раз. Не покладатися на pressure: звичайний дотик працює на iPhone. Сітка не з’їжджає після лопання, навколишній пластик зберігає прозорість. «Нова плівка», звук, вихід; без обов’язкового рахунку, балів, таймера чи проходження всіх клітин.

## 9. Нова сцена «Просто бісить»

Окремий стан доступний без пояснення причини. Текст: «Бісить? Можеш нічого не пояснювати. Обери, що хочеш розбити».

Вибір «Тарілка / Пляшка». Стартова сцена за 01: реалістична стіна, поверхня під нею, цілий предмет у зручній зоні захоплення. Drag відтягує/задає замах, release запускає кидок із напрямком та силою з жесту. Легкий жест теж працює; обмежити максимальну силу. Камера й стіна мають зрозумілу глибину. Предмет летить, стикається зі стіною і лише тоді розбивається.

Кераміка: різні нерівні шматки з видимою товщиною й глазур’ю. Скло: прозорі різні уламки з гострими гранями й відблисками. Відскок, обертання, гравітація, падіння на поверхню, згасання руху. Не конфеті, не однакові трикутники з будь-якого предмета, не вибух до контакту. Удар тарілки, розрив скла й дрібні падіння звучать по-різному. Гучність контрольована, без раптового надмірного піку.

Опційно «Написати, що бісить» на тарілці; текст локальний, не обов’язковий, без людей/облич як мішені. «Ще одну», «Прибрати уламки». Ліміт кількості тіл і плавне прибирання старих уламків, щоб серія кидків не гальмувала. Кнопка «Кинути» як доступна альтернатива. Не повідомляти, що руйнування гарантовано заспокоює; після можна запропонувати «Хочу тихішу сцену».

## 10. Свічка — «Хочу тиші»

Референс 02: світлий натуральний віск, підставка, справжній ґніт, тепла темна атмосфера й світло на навколишніх поверхнях. Початково свічка не горить. Людина бере запалений сірник та підносить до ґнота; полум’я виникає на ґноті після контакту. Сірник після цього згасає/забирається. Доступна кнопка «Запалити».

Невелике реалістичне полум’я з темнішим/синюватим низом і теплим верхом, природною асиметрією та м’яким рухом. Коливання світла й тіней узгоджені з ним. Невелика калюжка розтопленого воску й повільна зміна, без швидкого повного згорання. Дуже тихе рідкісне нерівномірне потріскування; не постійний гучний багаття-loop. Після згасання звук зупиняється, короткий тонкий дим від ґнота. «Загасити / Запалити», вимкнення звуку. Без таймера та нав’язаного завершення.

## 11. «Сумно й самотньо» — «Побудь тут»

М’який окремий шлях, що використовує готову свічку, а не змушує щось розбивати. Текст: «Можеш просто побути тут. Нічого не потрібно робити правильно».

Теплий куточок із чашкою чаю, свічкою й дощем за вікном. Це розширення тихої сцени: свічка повторно використовує той самий якісний компонент. Пара над чашкою, краплі на склі, повільні зміни теплого світла. Чашку можна притримати/легко повернути пальцем; на запітнілому вікні провести пальцем і залишити слід, який повільно затягується. Жодних заяв про реальне тепло від екрана.

Необов’язкове запитання «Чого тобі зараз найбільше бракує?» з можливістю пропустити; текст не надсилати в AI/аналітику. Без балів, вимоги закінчити вправу чи примусової позитивності. «Написати близькій людині» може запропонувати скопіювати «Мені сьогодні сумно. Маєш трохи часу побути зі мною на зв’язку?» або відкрити стандартне меню share після дії користувача; не надсилати нічого автоматично й не обирати адресата. Для чаю/вікна окремого згенерованого референсу в ZIP немає: витримай стиль свічки, не заявляй, що це готовий наданий asset.

## 12. Банка — «Хочу паузу»

Референс 04: одна бордова алюмінієва банка без брендів, холодні краплі, срібна кришка. Підказка «Підчепи кільце й потягни вгору». Можливий вибір «Пиво / Безалкогольне / Газований напій» без зміни погодженого вигляду та зайвих моделей. Не подавати алкоголь як спосіб вирішити самотність.

Кільце — окрема геометрія, кріпиться до заклепки. Палець піднімає вільний кінець; кільце повертається навколо кріплення, його носик продавлює надрізаний клапан УСЕРЕДИНУ. Після порога відкривання чіткий металевий «клац», потім коротке «пш-ш»; невеликі бульбашки біля отвору допустимі. Не фонтан піни, не відірвана кришка, не кільце, що літає окремо від банки.

Відкритий отвір має товщину, темну внутрішню частину; клапан усередині, кільце потім можна опустити. До порога незавершений жест повертає кільце, після відкриття банка лишається відкритою. Звук відкривання лише один раз на банку. «Нова банка», звук; «Відкрити банку» як кнопка альтернативи. Жест має бути доступний на малому екрані без ювелірної точності.

## 13. Наявні сцени, які треба зберегти

- Пряжа: заплутана бордова маса → витягування доступного кінця → круговий жест змотує цілісний клубок. Фактура, натяг і петлі; прогрес від жесту, не таймера/crossfade фото.
- Пісок/камінці: спочатку змішані в одному лотку; людина переносить окремі камінці на вільну частину тієї самої дошки, потім розрівнює пісок. Заглиблення та борозни зберігаються між жестами. Не додавати воду й не замінювати іншим задумом.
- Карта: паперовий об’єкт у міжнародно визнаних межах Росії без Криму та окупованих територій України, контур перевірений. «Рвати / Палити / Знищити» — умовна дія з папером, без людей або реальних цілей. Розрив/горіння змінюють об’єкт від місця дотику, не миттєва заміна фото.
- Невисловлене повідомлення: символічний чат, людина пише те, що не сказала; зрозумілі символічні статуси, нікого реально не контактуємо. Чат не є справжнім месенджером. Повідомлення не виходять у мережу/логи.

Уточнити підказки цих сцен простою мовою, не втратити їх механіки й узгоджений вигляд.

## 14. Підбір стану та AI

Онови серверний Cloudflare Workers AI classifier і локальний fallback під нові сцени. Збережи існуючу інтеграцію, не додавай платний сервіс чи billing. Перевір актуальні офіційні документи провайдера для моделі/доступності Free/квот/формату. Нові «інтеграції» тут здебільшого — нові інтерактивні сцени, жести й аудіо; не встановлюй сторонні сервіси без потреби.

| Приклад | Шлях |
|---|---|
| Борги, гроші, сума | Гроші, тільки гривні для вправи |
| Усе на мені, забагато обов’язків | Рюкзак |
| Думки по колу | Пряжа |
| Хочу навести лад | Пісок/камінці |
| Просто бісить, бісять люди, хочу щось розбити | Посуд; можна обрати плівку як альтернативу |
| Хочу полопати плівку | Плівка |
| Хочу тиші, спокійно посидіти | Свічка |
| Сумно, одиноко, самотньо | «Побудь тут» |
| Втомився, хочу паузу | Короткий вибір банка / плівка / свічка |
| Не висловив, не сказав | Символічний чат |
| Злість саме через війну | Карта; страх/горе не маршрутизувати автоматично в руйнування |

Пріоритет конкретного сенсу над одним словом «бісить». Кілька тем → «З чого почнемо?»; однозначна тема → сцена без повторної анкети. Заперечення, українська/російська/суржик і лайка. Не називати local keyword fallback AI. Людина завжди може змінити сцену.

Модель повертає лише валідований JSON із дозволеними categories/sceneIds, amount/currency та needsClarification. Ввід — дані, не інструкції; prompt injection не змінює системні правила, не виконувати HTML/JS з відповіді. Старі sceneIds мігрувати сумісно. Браузер звертається тільки до власного серверного endpoint, не напряму до Cloudflare.

Секрети CLOUDFLARE_ACCOUNT_ID / CLOUDFLARE_API_TOKEN / CLOUDFLARE_AI_MODEL тільки на сервері. Не відтворювати раніше оприлюднений токен; потрібне приватно налаштоване актуальне значення. .env.example без реальних значень, .gitignore, жодних NEXT_PUBLIC секретів. Timeout, payload limit, стійкий між serverless instances rate limit та бюджет. Скасувати старий запит, ігнорувати запізнілу відповідь. 401/403/429/5xx/offline/timeout/поганий JSON/відсутні env → локальна маршрутизація або ручний вибір без нескінченного spinner. Текст повідомлень і підписів сцен повторно не класифікувати.

## 15. Аудіо й продуктивність

У ZIP НЕМАЄ аудіофайлів. Підготуй власні/ліцензовані короткі samples, перевір джерела й права, збережи attribution. Не заявляй, що звук додано, якщо є лише назва файла або заглушка. Синтез допустимий, якщо реально звучить природно, а не однаковим beep у всіх сценах.

AudioContext розблоковувати явним жестом користувача; перевірити браузерні обмеження iOS. До першої дії не запускати звук автоматично. Один очевидний перемикач звуку, помірна гучність, локально зберігати лише цю налаштувальну перевагу. Синхронізація звуку з фізичним моментом. Ліміт одночасних samples, без clipping; зміна сцени/згасання/фон вкладки зупиняють відповідні loops. Відмова аудіо не ламає жест. Вібрація лише необов’язково й за підтримки, не вимагати її на iPhone.

Не завантажувати всі важкі сцени одразу: code splitting, оптимізовані текстури/моделі, дозавантаження вибраної сцени. Обмежений DPR на мобільному, бюджет уламків, інстансинг/пули де доречно, dispose ресурсів при виході. Рендер pause у фоні; для нерухомих сцен за можливості demand render. Ціль плавного жесту близько 60 fps на спроможних пристроях, для слабких — нижча деталізація без поломки механіки. Не вигадувати виміри. Без WebGL показати доступну альтернативу; не називати її повною 3D-симуляцією.

## 16. Постійні вимоги до всього сайту

- Мобільні 360/390/430 px і desktop: без накладань, обрізання предметів/цифр/кнопок та горизонтального скролу. Текст читабельний, зони дотику зручні, safe-area враховано. Підтримка клавіатури, фокусу, labels, семантики, контрасту, reduced motion; жести мають альтернативу.
- Hero/LCP доступні одразу; не lazy-load головний візуал і не ховати за loader. Оптимізувати images/fonts/video, responsive розміри, dimensions, lazy loading нижче hero, доречний cache/preconnect і critical CSS. Виміряти LCP/CLS/INP; розслідувати NO_LCP, не вигадувати причину.
- SEO: українські metadata, canonical фактичного домену, Open Graph, sitemap/robots, доречні structured data. GSC verification через конфігурацію, без вигаданих кодів і заяв про індексацію без перевірки. Приватні/службові сторінки не індексувати.
- Google/аналітика лише потрібні інтеграції. Загальні події без тексту переживань, сум, імен, повідомлень і підписів каменів. Без session replay приватного вводу/сцен. Технічні error logs без секретів/особистого змісту.
- Якщо є база/Storage: перевір схему, grants, RLS, політики рядків/колонок, RPC/views/SECURITY DEFINER, мінімальні права. Серверна авторизація для захищених операцій; не «дозволити все». Міграції з відкатом, не видаляти дані. Не вводити базу для текстів переживань.
- Якщо є форми/адмінка/оплати/бронювання/сповіщення, зберегти та перевірити потоки, серверну валідацію, сесії/cookies/CSRF, ідемпотентність/транзакції, підписи webhooks. Сповіщення не є єдиним записом заявки, передбачити повтор доставки. Не додавати ці функції, якщо їх немає й вони не потрібні.
- Loading/empty/error/offline, 404/500, доступність залежностей, HTTPS/домен, production env, квоти та призупинення безкоштовних сервісів. Аналіз конкретних ризиків і відновлення. Ніяких обіцянок «ніколи нічого не зламається».

## 17. Порядок та критерії приймання

Спочатку перевір репозиторій/референси, коротко зафіксуй карту змін. Далі прибери конфліктні валютні/глиняні маршрути, онови тексти й класифікатор. Потім доведи кожну нову механіку й звук; збережи наявні сцени. Не завершуй відповідь після плану. Не лишай наступні сцени як «потім» без конкретного зовнішнього блокера.

Перевір build/lint/types відповідно до проєкту. Змістовні тести/перевірки:

| Сцена | Що має бути доведено |
|---|---|
| Гроші | Не вантажаться USD/PLN; коректна гривня; одна дія одне списання; точний нуль; інша валюта не перейменована мовчки |
| Рюкзак | Камені окремі; бігунок слідує траєкторії; часткове закривання зберігається; зубці/тканина змінюються послідовно; звук тільки під час руху |
| Плівка | Натискання в конкретному пухирці; одноразовий pop; стійкий сплющений стан; проведення по кількох клітинках; нова плівка |
| Посуд | Цілий предмет → політ → контакт → уламки; різні матеріали/звуки; серія кидків не накопичує нескінченні тіла |
| Свічка | Контакт зі ґнотом запалює; природне полум’я/світло; рідкісне тихе потріскування; згасання зупиняє звук |
| Банка | Кільце на заклепці, клапан всередину; до порога можна відпустити; після банка відкрита; звук один раз; нова банка |
| Самотність | Тихий шлях; свічка/чай/вікно працюють; особистий текст не витікає; кнопка близькій людині не надсилає автоматично |
| Hero/тексти | «Видихай» повітряно по літерах один раз; без CLS; зрозумілі кнопки; reduced motion; передача тексту пояснена коротко |
| Підбір | Прості/змішані/неоднозначні фрази; заперечення; prompt injection; timeout/429/поганий JSON/відсутні env; запізнілі запити |

Перевір pointercancel, відпускання поза сценою, швидкі повтори, multi-touch без дублювань, resize, фон вкладки, вихід/restart, mute, відмову WebGL/аудіо. Регресія пряжі/піску/карти/чату. Supabase Security Advisor якщо застосовний; доступ гостя/користувача/адміна й чужі дані якщо вони є. Live AI лише якщо є приватні env, на вигаданих прикладах.

Візуальне QA: для кожної нової/зміненої сцени зніми початковий, проміжний і кінцевий стан на 390 px та desktop, порівняй із відповідним референсом. Запиши коротке відео жесту зі звуком для кожної нової механіки. Якщо немає можливості записати — явно назви, які перевірки виконані і як повторити решту. Скриншот не доводить робочий drag/звук. Емуляцію не називай тестом на фізичному iPhone.

Перед фінальним звітом самостійно виправ видимі дефекти: плоскі предмети, неприродний матеріал, різкі стрибки, обрізання, відсутні звуки, непрочитані референси, гальмування. Не підмінюй повний результат демонстраційними заглушками.

У звіті: що зроблено, використані файли/звуки й права, build/lint/type результати, скриншоти/відео, виміряна продуктивність, live AI статус, потрібні env/redeploy, точні зовнішні блокери та що не перевірено. Реалістичність треба показати, а не лише назвати. Не гарантуй ідеал з першого запуску: виконай власну перевірку й виправлення до передачі результату користувачу.
