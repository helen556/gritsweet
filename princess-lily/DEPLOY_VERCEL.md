# Публікація на Vercel — покроково

Збірку перевірено командою `vercel build` (Vercel CLI) на чистій базі PostgreSQL: збірка успішна, під час неї автоматично
створюються таблиці, налаштування оплати (manual-link з посиланням monobank), чернетка книжки й перша власниця.

> Потрібна безкоштовна база **PostgreSQL** (Neon або Supabase). SQLite на Vercel не працює — файлова система там лише для читання.

## Спосіб А (рекомендовано): імпорт із GitHub
1. https://vercel.com → **Add New… → Project** → **Import** репозиторію `helen556/gritsweet` (гілка `claude/new-session-em7q3n` або після злиття — `main`).
2. **Root Directory → `princess-lily`** (важливо: у репозиторії є інший проєкт у корені). Framework визначиться як Next.js.
   Build Command змінювати не треба — його задає `vercel.json` (`npm run vercel-build` = створення таблиць + `next build`).
3. Ще до першого деплою створіть базу: у проєкті Vercel → **Storage → Create Database → Neon (Postgres)** → Connect.
   Vercel сам додасть `POSTGRES_URL` (його застосунок підхоплює автоматично). Або вставте свій рядок Supabase/Neon у `DATABASE_URL`.
4. **Settings → Environment Variables** (Production; після збереження — Redeploy):

   | Змінна | Значення |
   |---|---|
   | `SESSION_SECRET` | випадкові ≥ 32 символи (`openssl rand -base64 32` або будь-який генератор паролів) |
   | `APP_URL` | `https://<назва-проєкту>.vercel.app` (адреса, яку показав Vercel) |
   | `ADMIN_EMAIL` | email власниці для входу в `/admin` |
   | `ADMIN_INITIAL_PASSWORD` | надійний пароль ≥ 12 символів (після першого входу змініть в адмінці й видаліть змінну) |
   | `CRON_SECRET` | випадковий рядок (щоденний повтор невдалих сповіщень/листів) |
   | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | необов’язково зараз; див. `docs/TELEGRAM.md`. Токен — лише сюди, не в чат |
   | `DATABASE_SSL` | лише якщо в логах збірки помилка сертифіката (Supabase pooler): `no-verify` |

5. **Deploy**. Після завершення відкрийте `https://<проєкт>.vercel.app/uk` на комп’ютері й телефоні, увійдіть у `/admin`.

## Спосіб Б: з архіву (ZIP)
У Vercel немає завантаження ZIP через сайт, тому архів використовують так:
- **через новий репозиторій GitHub**: розпакуйте, завантажте вміст у новий репозиторій (Add file → Upload files), далі Спосіб А з Root Directory = корінь;
- **або через Vercel CLI** (Node.js 20+): у розпакованій теці `npm i -g vercel`, `vercel login`, `vercel link` (створить проєкт),
  додайте змінні (`vercel env add …` або на сайті, як у таблиці вище) і базу Storage → `vercel deploy --prod`.

## Що працює на демо-адресі
- Вітрина uk/en, повноекранне відео, ефекти, авторка, FAQ, контакти; книжка «Незабаром» (ціни ще немає — покупка неактивна, як і має бути).
- Адмінка `/admin`: товари, CRM замовлень з експортом Excel/PDF, звернення, налаштування оплати й контактів.
- Контактна форма зберігає звернення в базі.

## Обмеження безкоштовної демо-версії (чесно)
- **Файли, завантажені з адмінки** (нові обкладинки, фото авторки, PDF книжок, квитанції), на Vercel зберігаються лише тимчасово.
  Для постійного зберігання потрібне сховище: `PRIVATE_STORAGE=supabase` + `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` і `supabase/policies.sql`
  (PDF і квитанції); для публічних обкладинок — окреме доопрацювання. Вбудовані зображення й відео з пакета працюють постійно.
- Email-листи з PDF не надсилаються, доки не підключено провайдера (`EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, `EMAIL_FROM`).
- Telegram-сповіщення запрацюють після додавання токена й chat_id і перевірки тестовим замовленням.
- Еквайринг monobank (`mono-acquiring`) не перевірений наживо — для демо використовуйте `manual-link`.
- Cron на безкоштовному тарифі Vercel — раз на добу (повтори сповіщень також доступні кнопкою в адмінці).
