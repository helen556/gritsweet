# «Історії принцеси Лілі» / Princess Lily Stories — інтернет-магазин

Невеликий двомовний (uk/en) магазин дитячих книжок: вітрина, кошик без реєстрації, оформлення,
сторінка статусу замовлення, платіжний адаптер, приватна видача PDF, доставка Новою поштою, захищена адмінка.

> **Статус:** робоча локальна версія. Сайт **не опублікований**. Платіжний провайдер, email-провайдер,
> справжні PDF, ціни та реквізити ще не надані — відповідні інтеграції **чесно вимкнені** й показують це
> (на вітрині «Незабаром», оформлення — сторінка «Оплата тимчасово недоступна», в адмінці — «не налаштовано»).

Це окремий застосунок у теці `princess-lily/` репозиторію (поруч — інший проєкт, його не змінено).

## Стек
- **Next.js 16** (App Router, TypeScript, Turbopack), React 19, Tailwind CSS 4.
- **Kysely** — один код для **SQLite** (розробка) і **PostgreSQL** (production, напр. Supabase). Схема — `src/db/migrate.ts`.
- `jose` (підписаний HttpOnly-cookie сесії), `bcryptjs`, `zod`, `sharp` (зображення).
- Шрифти: Cormorant (заголовки) + Manrope (текст) — обидва OFL, з кирилицею, **локально** через Fontsource.

## Швидкий старт
```bash
cd princess-lily
cp .env.example .env                 # заповніть SESSION_SECRET (openssl rand -base64 32)
npm install
npm run db:setup                     # таблиці + чернетка товару з наданою обкладинкою
npm run admin:create -- you@example.com   # виводить тимчасовий пароль ОДИН раз (або ADMIN_PASSWORD=…)
npm run dev                          # http://localhost:3000 → /uk ; адмінка — /admin
```
Без платіжних/email ключів сайт працює: книжка показується як «Незабаром», оформлення вимкнене.

### Перевірити покупку локально (демо)
```bash
DATABASE_URL=file:./data/demo.db npm run demo:fixtures          # «[DEMO]» товар; відмовляється в production
DATABASE_URL=file:./data/demo.db ADMIN_PASSWORD='Garden-Path-Lantern-2026' npm run admin:create -- owner@example.com
DATABASE_URL=file:./data/demo.db PAYMENT_MODE=provider PAYMENT_PROVIDER=test \
  PAYMENT_WEBHOOK_SECRET=dev_only EMAIL_PROVIDER=outbox npm run dev
CHROMIUM_PATH=… npm run test:e2e                                  # наскрізна перевірка (див. нижче)
```
Тестовий провайдер (`PAYMENT_PROVIDER=test`) і `EMAIL_PROVIDER=outbox` **ігноруються при `NODE_ENV=production`**.

## Оплата
`PAYMENT_MODE`:
- **`disabled`** (за замовчуванням) — замовлення не створюються, `/uk/checkout` → «Оплата тимчасово недоступна».
- **`manual_link`** — звичайне платіжне посилання без API (задається в адмінці → Налаштування).
  Замовлення зберігається **до** переходу на оплату; покупець бачить суму, номер замовлення для призначення платежу,
  кнопку «Я оплатив(ла)» (лише позначка `pending_verification`, **нічого не видає**). Адміністратор звіряє
  надходження і натискає «Оплату звірено — підтвердити» → запускається видача PDF / підготовка до відправлення.
  **У цьому режимі автоматичної видачі немає** — і FAQ/«Доставка й оплата» автоматично кажуть «після підтвердження оплати».
- **`provider`** — провайдер з API і **підписаним вебхуком**. Конкретний провайдер ще не обраний; є інтерфейс
  `PaymentAdapter` (`src/lib/payments/providers.ts`): `createCheckout()` і `parseWebhook()` (перевірка підпису).
  Вебхук: `POST /api/payments/webhook/<provider>`. Обробка (`src/lib/fulfillment.ts`):
  - підпис невірний → 401; невідомий/неактивний провайдер → 404;
  - перевірка `order_id`, **суми в копійках** і **валюти** відносно збереженого замовлення; розбіжність → `pending_verification` + нотатка;
  - **ідемпотентність**: унікальний `(provider, event_id)`, перехід у «оплачено» умовним оновленням рівно один раз;
  - success-URL з браузера лише показує сторінку статусу, **нічого не підтверджує**.

  Щоб підключити, напр., LiqPay/WayForPay/monobank: реалізувати адаптер, зареєструвати в `adapters`, задати
  `PAYMENT_MODE=provider`, `PAYMENT_PROVIDER=<id>`, `PAYMENT_WEBHOOK_SECRET` (або ключі провайдера), прописати URL вебхука в кабінеті провайдера.

Ціни зберігаються в **копійках** (`integer`), підсумки рахує сервер з каталогу; ціни з браузера ігноруються.
Зміна ціни не змінює вже оформлені замовлення (`order_items` — знімок назви, мови, формату й ціни).

## Видача електронних книжок
- PDF зберігаються в **приватному сховищі** (`PRIVATE_STORAGE=local` → `storage/private/`, або `supabase` → приватний bucket), ніколи не в `public/`.
- Після оплати: лист з **особистими посиланнями з обмеженим строком** (`DOWNLOAD_LINK_TTL_HOURS`, за замовч. 72 год)
  і кількістю завантажень (`DOWNLOAD_MAX_COUNT`, 5). У БД — лише SHA-256 хеші токенів. Скасоване/неоплачене замовлення → посилання не працюють.
- Email-адаптер (`src/lib/email`): `resend` (HTTP API) або `none`. Журнал `email_deliveries`: статус, спроби, остання помилка,
  наступна спроба (5 хв → 30 хв → 2 год → 12 год, до 5 спроб). Дублікати виключені ключем `dedupe_key`.
  В адмінці: «Надіслати лист повторно» і «Створити посилання для ручного надсилання» (коли email не налаштовано).
- **Стан зараз:** email-провайдер і справжні PDF відсутні → у замовленні буде «email не налаштовано», без імітації успіху.

## Доставка (Нова пошта)
Адаптер `src/lib/delivery/nova-poshta.ts`. Без `NOVA_POSHTA_API_KEY` — ручне введення міста та відділення/поштомату
з підписами полів; з ключем — підказки з API (`getCities` / `getWarehouses`; **не перевірено без ключа**).
Тариф не розраховується: «за тарифами перевізника, оплачує покупець». Статус доставки окремий від статусу оплати;
ТТН вводить адміністратор, покупець бачить її на сторінці статусу.

## Адмінка `/admin`
- Вхід email+пароль; сесія — підписаний HttpOnly cookie (12 год, SameSite=Strict) з перевіркою по БД (неактивний користувач / зміна пароля анулює сесії).
- **Кожна** сторінка, server action і API адмінки викликає `requireAdmin()`/`getAdmin()` на сервері. Ролі: `owner` (усе) і `staff` (без налаштувань, журналу, завантаження PDF).
- Пароль за замовчуванням не створюється; прості паролі (`admin`, частина email, < 12 символів) відхиляються.
- Ліміт спроб входу: 10/15 хв з IP і 8/15 хв на обліковий запис.
- Функції: товари (статус: чернетка / незабаром / опубліковано), переклади uk/en (з позначкою «переклад погоджено»), обкладинки,
  варіанти «мова книжки × формат», ціни, залишки, примітка про надходження, приватне завантаження PDF; замовлення (пошук, фільтр,
  деталі, події платежу, ручне підтвердження оплати, скасування, доставка/ТТН, повторне надсилання PDF, нотатки); звернення;
  налаштування контактів і платіжного посилання; зміна пароля; **журнал дій** (`audit_log`).
- Зручно з телефона: нижня панель розділів, поля ≥ 44 px.

Товар продається лише якщо: статус «Опубліковано», варіант увімкнено, ціна > 0, є PDF (для PDF) або залишок (для друку).

## Схема даних
`products`, `product_translations`, `product_variants` (locale, format, price_minor, stock, private_pdf_key),
`orders`, `order_items` (знімок), `payment_events`, `fulfillments` (digital / shipping, ТТН), `download_grants`,
`email_deliveries`, `contact_messages`, `settings`, `audit_log`, `admin_users`, `rate_limits`. Див. `src/db/migrate.ts` і `src/db/types.ts`.

## Production (Supabase / Postgres)
1. Postgres: `DATABASE_URL=postgres://…` (Supabase → Connection string). `npm run db:setup`.
2. Виконати `supabase/policies.sql`: RLS увімкнено на всіх таблицях, доступ для `anon/authenticated` заборонено;
   приватний bucket `private-books` (лише PDF, до 100 МБ). `PRIVATE_STORAGE=supabase`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
3. Обкладинки, завантажені з адмінки, пишуться в `UPLOADS_DIR` (локальний диск). Для serverless-хостингу без постійного диска
   потрібен постійний том або перенесення обкладинок у публічний bucket (не реалізовано).
4. `APP_URL=https://<домен>` (canonical, hreflang, sitemap, посилання в листах).
5. Cron: `npm run email:retry` кожні 10 хв.

## SEO, доступність, швидкість
- Маршрути `/uk` (за замовчуванням) і `/en`, окремі словники (`src/i18n`), перемикач зберігає сторінку й параметри; мова сайту ≠ мова книжки.
- Унікальні title/description, canonical, hreflang uk/en/x-default, `sitemap.xml`, `robots.txt`; noindex для адмінки, кошика, оформлення,
  замовлень, завантажень і чернеток оферти/політики. Open Graph — наявна обкладинка. Schema.org Product/Offer — лише для опублікованих товарів з ціною, без рейтингів.
- Перед запуском: реальний домен у `APP_URL`; верифікацію Google Search Console додати після отримання (не вигадано).
- Аналітика: `NEXT_PUBLIC_ANALYTICS_PROVIDER=plausible` + `NEXT_PUBLIC_ANALYTICS_DOMAIN` (без cookie й персональних даних); без змінних — нічого не завантажується.
- LCP — постер hero з `preload`/`fetchpriority=high`; відео підвантажується після гідратації; CSS вбудовано (`inlineCss`); стабільні розміри медіа.

## Потрібно від власниці
