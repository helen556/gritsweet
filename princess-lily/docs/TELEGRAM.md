# Telegram-сповіщення: інструкція для власниці

Бот магазину вже створений (через BotFather), чат із ним відкрито й натиснуто **Start**.

## Що приходить
- **Нове замовлення** — одразу після того, як замовлення збережене: номер, київський час, ім’я покупця, коротко товари, сума, формат/доставка, статус оплати («очікує оплату — НЕ підтверджено») і захищене посилання в адмінку (відкривається лише після входу).
- **Оплату підтверджено** — ТІЛЬКИ після реальної перевірки: підписаний вебхук платіжного сервісу або ваше ручне «Оплату звірено — підтвердити» в адмінці. Натискання покупцем посилання на оплату чи «Я оплатив(ла)» такого повідомлення НЕ надсилає.

Повідомлення не дублюються (кожне має унікальний ключ), невдалі спроби повторюються з паузами; якщо Telegram недоступний, замовлення все одно зберігається, а в адмінці (Огляд → «Telegram: не доставлено» і картка замовлення) видно помилку й кнопку «Повторити надсилання».

## Підключення (робить розробник/адміністратор сервера)
1. Токен бота вводиться **тільки** в змінні середовища платформи (Vercel → Project → Settings → Environment Variables → `TELEGRAM_BOT_TOKEN`) і в локальний `.env`. Не пересилайте токен у чат, пошту, ZIP чи репозиторій.
2. Отримати `chat_id` (офіційний метод `getUpdates`): напишіть боту `/start` (для групи — будь-яке повідомлення в групі, куди додано бота), потім на сервері/локально:
   `TELEGRAM_BOT_TOKEN=… npm run telegram:chat-id` → скопіюйте `TELEGRAM_CHAT_ID=…` у змінні середовища.
3. Перезапустіть/перерозгорніть сайт, оформіть тестове замовлення й переконайтеся, що повідомлення прийшло (в картці замовлення статус «доставлено»).
4. Групу використовуйте лише приватну, з довіреними людьми — у повідомленнях є імена покупців.

## Якщо токен розкрито
BotFather → `/mybots` → ваш бот → **API Token → Revoke current token** → новий токен у змінні середовища → перерозгорнути. Старий токен одразу перестає працювати.
